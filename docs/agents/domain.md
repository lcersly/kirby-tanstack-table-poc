# Domain docs

## Before exploring

Read `GLOSSARY.md` at the repo root, or `GLOSSARY-MAP.md` if present and the relevant context glossary it points to. Read ADRs in `docs/adr/` that concern the area being explored. If these files do not exist, proceed without flagging their absence; create them only when a term or decision is ready to record.

## Use the glossary

Use domain terms as defined in the glossary. If a needed term is missing, note the gap instead of inventing synonyms.

## Flag ADR conflicts

If a proposal conflicts with an existing ADR, name the ADR and explain why it may need to be reconsidered. Do not silently override it.

## Layout

This is a single-context repo. Keep `GLOSSARY.md` at the root and ADRs in `docs/adr/`.
